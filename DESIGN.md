## Overview

**The Flight Deck.** WOMBATpass is an Operate surface: operators scan cloud infrastructure, review compliance findings, and decide what to fix. The aviation language (Flight Operations Center, journey, briefing, wall mode) is product vocabulary, not decoration. The interface stays dense, calm and scannable; brand appears in precise details rather than loud surfaces.

Both themes are first-class. The page uses light by default and switches through `data-theme="light"` / `data-theme="dark"` on `<html>`; `color-scheme` follows so native controls and popups match. Tokens live in `src/index.css` under `:root` and `[data-theme="dark"]`.

## Colors

- **Brand** `#0094FF` is the signal colour. It is not a text colour on light surfaces and not a white-text background: use `--waf-brand-ink` for text/icons on light, and `--waf-brand-btn` for filled buttons.
- **Neutrals** are tonal: `--bg`, `--surface`, `--input-bg`, `--border`, `--text`, `--muted`. Never introduce a new page background or a second grey ramp.
- **Severity** is semantic and shared. Always use `severityColor`, `severityBg` and `severityBorder` from `src/severity.ts`; never redeclare a `SEV_COLOR` map. The CSS tokens are `--sev-critical`, `--sev-high`, `--sev-medium`, `--sev-low` and have light/dark variants.
- **Scores** use the ink variants (`--score-high-ink`, `--score-mid-ink`, `--score-low-ink`) for text, and `scoreColor` / `scoreBg` / `scoreBorder` from `src/severity.ts` for UI accents.
- **Status** colours (`--pass`, `--fail`, `--skip`, `--waived`) are reserved for pass/fail/skip/waived status, not general decoration.
- Text contrast must meet WCAG AA: 4.5:1 for normal text, 3:1 for large text and non-text UI. Prefer a darker token over larger type.
- **Legacy palette:** the `legacy-*` entries in the frontmatter capture colours still present in older pages. New work must use the named tokens above; treat the legacy entries as migration debt, not as an invitation to add more.

## Typography

- System sans stack; no display fonts. The product is a tool, not a campaign.
- Scale: title 1.35rem / 800, heading 0.95rem / 800, label 0.75rem / 700, micro 0.7rem / 700, body 14px.
- **Legibility floor:** body text ≥12px, functional text (labels, values, buttons, nav, table cells) ≥11px. Do not use 9–10px text to fit dense layouts; let cards grow taller.
- Uppercase micro-labels are allowed at 0.7rem with letter-spacing, but remain functional text and must meet the 11px floor.
- Monospace is reserved for IDs, scores, code and control identifiers.
- All legacy font sizes are mapped to the ramp above; do not introduce off-ramp sizes or sizes below the legibility floor.

## Layout

- Fixed top navigation; page content lives in `main` and is 90% wide, centred, with a 1.5rem/2rem padding on desktop. Do not stack a second full page gutter on mobile.
- Maximum content width 1680px, enforced in `src/index.css`.
- **Widget board:** 12-column grid, 1rem gap. Widget sizes: small = 3 columns, medium = 4, large = 6. At ≤1360px: 4/6/12. At ≤900px: every widget spans 12. Use `minmax(0, 1fr)` so long values never force horizontal scroll.
- Breakpoints in use: 1360px (tablet grid), 900px (single column + mobile headers), 760px (page-level mobile), 640px (compact overlays).
- On narrow screens widget headers wrap: the title takes a full row and the edit controls sit below it. Never let controls squeeze the title to zero width.
- Touch targets are 44×44px under `@media (pointer: coarse)`; fine pointers may use 24px icon buttons.

## Elevation & Depth

- Flat, tonal surfaces. Cards use `--surface` on `--bg` with a 1px `--border` and **no shadow**; `--shadow-sm` / `--shadow-md` are reserved for floating overlays (menus, popovers, modals).
- No coloured glow shadows, no radial halos, no gradient text, no two-axis grid overlays. Cards do not use a thick accent border on one side.
- Modals use a single strong elevation (`0 24px 70px rgba(0,0,0,.3)`) and a dim backdrop.

## Shapes

- Radius scale: 8px (controls, buttons, inputs), 10px (inner surfaces), 12px (cards, panels), 16px (hero/media panels), 999px (pills, chips).
- Status is expressed with a small dot, a pill, a tinted full border or the status text — never a 3–4px bar on the left or right edge of a rounded card.
- Icon buttons are square with the same radius as their container; do not mix circular and square icon buttons in one row.

## Components

- **Top navigation:** fixed, translucent `--nav-bg`, 1px `--nav-border`, logo left, run selector and utility actions right. The 9-dot launcher replaces category dropdowns when the beta feature is enabled.
- **Cards:** `--surface`, 1px `--border`, 12px radius, no shadow. Header is title + optional meta; card actions stay in a single row on desktop and wrap below the title on mobile. Prefer `ui/Card`.
- **Buttons:** primary uses `--waf-brand-btn` + white; secondary uses surface + border; danger states use `--fail-ink`. Focus ring is a 2px `--waf-brand-ink` outline with 2px offset. Every icon-only button needs an `aria-label`.
- **Forms:** every input/select/textarea has a visible or programmatic label. Selects share the themed appearance from `src/index.css`; do not opt out unless the control draws its own arrow.
- **Modals:** `role="dialog"`, `aria-modal="true"`, labelled by the heading. On open, move focus into the panel; trap Tab; close on Escape; restore focus to the trigger; lock background scroll.
- **Pills and chips:** 0.7rem/700, pill radius, muted text on `--bg`. Severity pills use the shared severity tokens.
- **Widget board:** widgets are product-specific data cards or user content. Catalogue, default layout and instance ids live in `src/widgets/types.ts`; renderers in `src/widgets/DashboardWidgets.tsx`; the page in `src/pages/MyDashboardPage.tsx`.
- **Content widgets:** text is plain text (2,000 char cap); logo accepts an http(s) image URL or an uploaded image (180 KB cap); iframe accepts http(s) only and renders sandboxed without `allow-same-origin`.
- **Sharing:** a share link encodes layout, text and embed/image URLs only. It never carries run data or identity, and importing it grants no access — recipients see their own RBAC-scoped data.

## Primitives

Shared UI lives in `src/ui/`. New pages compose these; do not re-implement page shells, tables or dialogs.

| Primitive | Purpose |
|---|---|
| `PageHeader` | The page's only `<h1>`: title, description, eyebrow, actions |
| `Card` | Padded panel with optional title/subtitle/actions; `padding="none"` for edge-to-edge tables |
| `DataTable` | Typed columns/rows, skeleton loading, empty state, horizontal scroll |
| `EmptyState` | Composed empty state with title, description and action |
| `Skeleton` / `SkeletonText` / `SkeletonRows` | Layout-shaped loading placeholders |
| `Button` / `buttonClass` | Variants (primary, secondary, ghost, danger) for buttons and links |
| `Input` / `Select` | Labelled form controls with hint, error, required marker and generated id wiring |
| `Tabs` | Controlled segmented tabs with optional counts and arrow-key focus movement |
| `Toolbar` | Filter/action bar with left and right slots that wrap on narrow screens |
| `StatTile` | KPI tile with tabular value and a semantic tone (neutral/pass/warn/fail/info) |
| `ChartFrame` + `CHART_*` | Chart panel wrapper plus the shared token-based palette, axis, grid and tooltip styles |
| `Modal` | `role="dialog"`, focus trap, Escape, scroll lock, focus restore |

Rules: import from `src/ui`; style with the `.ui-*` classes in `src/index.css`; never restyle a primitive inline. Progress against this standard is tracked in [`DESIGN-AUDIT.md`](./DESIGN-AUDIT.md).

## Do's and Don'ts

**Do**
- Use the CSS tokens and the shared `src/severity.ts` helpers.
- Let cards wrap and grow rather than shrinking text below the legibility floor.
- Give every interactive control a focus state and an accessible name.
- Keep data visibility server-scoped; the dashboard only renders what the API returns for the user's role, mandate and groups.
- Keep sharing explicit: show the generated link and explain that imported widgets use the recipient's data.

**Don't**
- Don't hard-code severity or score palettes in a page; add a token or use `severity.ts`.
- Don't use thick single-side accent borders on cards; use a dot, pill, tinted border or status text.
- Don't use coloured glows, cyan/purple gradient washes, gradient text or decorative grid overlays.
- Don't put white text on the bright brand blue, or brand-blue text on a light tint; use the ink/button tokens.
- Don't ship functional text below 11px or body text below 12px.
- Don't build a modal without focus entry, a focus trap, Escape handling and focus restore.
- Don't embed arbitrary URLs without `sandbox`, scheme validation and a clear warning that some sites refuse framing.
